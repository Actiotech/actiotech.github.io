01 / APPLICATIONS / APIs / BUSINESS LOGIC

Penetration Testing

Investigate how weaknesses in your applications and APIs could affect real users and business workflows.

What we assess

Agree the application endpoints, roles, environments, and business-critical journeys to assess. Testing can cover authentication, access control, input handling, sessions, and workflow abuse, with scope defined before work begins.

What you take away

A technical account of validated findings, their impact, reproduction evidence, and practical remediation guidance. Retest scope and timing are agreed with you.

02 / DISCOVERY / TRIAGE / PRIORITISATION

Vulnerability Assessment

Identify and prioritise weaknesses across an agreed set of assets, with context for remediation.

What we assess

Define the asset inventory and permitted checks. Review discovered vulnerabilities, exposed services, and configuration weaknesses, and distinguish tool observations from findings that have been validated.

What you take away

A prioritised view of identified issues, affected assets, validation status, and recommended next steps. Deeper exploitation requires an explicitly agreed penetration testing scope.

03 / THREAT MODELLING / DESIGN REVIEW

Security Architecture

Examine trust boundaries and data flows before design decisions become expensive to change.

What we assess

Review application diagrams, identity flows, integrations, sensitive data handling, and service boundaries. Discuss plausible abuse cases and the controls intended to prevent them.

What you take away

Documented design risks, assumptions, and recommended control changes, with priorities that help engineering teams plan their implementation.

COMMON QUESTIONS

Clarity before testing begins.

How do you use OWASP guidance?

OWASP provides useful reference material for requirements and testing. We select applicable checks for the agreed scope, using the Web Security Testing Guide, ASVS, and relevant risk categories. Using these resources does not imply OWASP certification or endorsement.

Is a vulnerability assessment the same as a penetration test?

No. A vulnerability assessment identifies and prioritises weaknesses. A penetration test investigates whether selected weaknesses can be used to produce a meaningful impact, subject to the engagement’s rules and constraints.

Does testing guarantee that an application is secure?

No assessment can establish the absence of all vulnerabilities. Results relate to the tested version, access provided, scope, and testing period. The report should state exclusions and limitations.

Can an assessment include Atlassian apps?

Discuss the app’s Forge modules, remote services, exposed endpoints, data flows, and permission model with us. Any assessment must be limited to authorised app-owned assets and respect the platform’s testing rules.
